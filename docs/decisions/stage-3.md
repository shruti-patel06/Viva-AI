# Stage 3 decision log: Question pool

- **Questions are written before the exam, by the worker, one job per experiment.** Live generation would put 60 students behind the AI service's per-minute limit at the moment they are waiting, and nobody could check a question before a student hears it. Precomputing means the exam itself makes no language-model calls for the pool, and every student's questions come from a pool the teacher has already read. Rejected: writing questions live during the viva (kept only for own-code questions in stage 8, which cannot be prepared).
- **The model's output is untrusted input.** It must match a strict JSON schema, and `check_question_set` keeps only complete questions in the slots that were asked for. An experiment needs 3 good questions in each of its 4 pool slots (12, as in the capacity estimate) or the whole set is rejected and retried. Running generation again replaces only that manual's drafts for that experiment; questions the teacher approved or rejected are never touched.
- **The language model sits behind one `get_language_model()` interface, with Groq by default and Gemini as an option.** A "too many requests" reply is not a failure: `RetryLater` puts the job back after the wait the provider asked for, without using up one of its 3 attempts. Each question records its prompt version and model, so prompts can be compared in the scoring study.
- **Nothing reaches a student until a teacher approves it.** Editing a question sends it back to draft and drops its audio, so the teacher always approves the exact wording students will hear. Rejected: auto-approving and letting teachers remove bad questions afterwards, because a wrong key point becomes a wrong mark.
- **Audio is made once, on approval, and the file is named after a hash of the question text.** The text is the cache key: an edit gives a new name, so old audio can never play for new wording, and running the job twice for the same text does nothing. The bucket is private and the API hands out links that expire after 10 minutes. Rejected: text to speech during the exam, which would make 300 calls at the busiest moment and miss the 1-second start target.

# Stage 2 decision log: Ingestion

- **The queue is a Postgres `jobs` table, not in-memory background tasks or Redis.** A row survives a server restart, commits in the same transaction as the document it belongs to, and needs no extra service. Workers claim jobs with `FOR UPDATE SKIP LOCKED`, so two workers never take the same job and neither waits for the other. Redis can replace the table if load ever needs it.
- **Every job must be safe to run twice.** A worker that dies leaves its job `running`; after 10 minutes (`locked_at`) it is put back in the queue and run again. The ingest job deletes the document's old chunks before adding new ones, so a second run replaces instead of duplicating. Rejected: trying to guarantee exactly-once execution, which a crash can always break.
- **Retries wait longer each time (30s, 60s), up to 3 attempts, but some errors fail at once.** A missing experiment title or a scanned PDF will not fix itself, so `PermanentJobError` skips the retries and shows the teacher the reason.
- **Manuals are split by matching the subject's experiment titles as headings.** Working from the last experiment backwards, each takes its last heading before the next one, which skips a contents page. Rejected: one PDF per experiment, which pushes the splitting work onto the teacher.
- **Embeddings sit behind one `get_embedder()` interface, with a local model by default and Gemini as an option.** The local model is free, offline and unlimited. Each model gets its own Chroma collection, since vectors from different models cannot be compared, and Chroma can be rebuilt from the uploaded files. Groq was considered but is not reliably documented as offering embeddings; it fits question generation and scoring better.

# Stage 1 decision log: Foundation

- **Local Supabase in Docker, not a hosted project.** Free, offline and resettable with `supabase db reset`; the hosted project comes at deploy time. Note: `config.toml` only configures the local stack, so the token hook and anonymous sign-in limit must be set again in the hosted dashboard.
- **Students sign in anonymously and the roll number lives on `sessions`, not `users`.** Each browser gets a new anonymous login, so a roll number is a fact about one sitting of one exam. `unique (exam_id, roll_number)` lets the database itself refuse a second viva. Rejected: teacher-created student accounts, which mean passwords to hand out for every batch.
- **The role comes from `app_metadata`, copied into the token by a hook.** Only the service key can write `app_metadata`; `user_metadata` is editable by the user, so trusting it would let anyone sign up as a teacher. A login with no valid role gets no `users` row and so sees nothing. Rejected: turning off email sign-up, because in this Supabase version that also blocks teacher logins.
- **The browser may only read; every write goes through the API.** `authenticated` gets `SELECT` only, filtered by policies, so the forward-only session rules can't be skipped by writing to the database directly. Rejected: insert policies for answers, which would bypass the session state machine.
- **Students never read `questions` or `scores` directly.** RLS filters rows, not columns, and teachers and students share the `authenticated` role, so reading a question row would expose its reference answer and key points. The API will serve only the current question's text.

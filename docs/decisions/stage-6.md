# Stage 6 decision log: Voice

- **Speech to text is the one live AI call, so it is built to fail without harm.** `speech.transcribe()` turns every kind of failure (no key, timeout, connection error, 429, 5xx, a refused file) into one `SpeechUnavailable`, and the API answers 503 with "Type your answer instead, or try recording again". The session is checked before the call and again after it, but no row is locked while the speech service works, so a slow call holds up nobody else. Typing is always on screen, and the page offers voice only where the slot is spoken and the browser can record. Rejected: queueing transcription like scoring, because the student must read and confirm the transcript before moving on.
- **The student confirms the transcript, and both versions are kept.** What speech to text heard is gathered on the server (`session_questions.transcript`, kept across a refresh like hints) and copied to `answers.spoken_transcript` on submit, beside the text the student confirmed. Comparing the two gives the spec's "transcript corrections" metric without trusting the browser to report it. The recording itself is not stored: whether answer audio is kept, and for how long, is still to be agreed with faculty.
- **Recordings are capped at 30 seconds and can be made in parts.** Sarvam's live endpoint takes at most 30 seconds a request, while a spoken answer runs about 45. The page stops at 30 seconds, and each further recording is added to the answer. Rejected: Sarvam's batch API for long audio, which answers in minutes, not seconds.
- **Question audio is the file made at approval, played from a link that expires in 5 minutes.** Nothing is synthesised during the exam, so playback costs no speech call and does not depend on Sarvam being up. The question is always on screen as well, so missing audio or a browser blocking autoplay costs nothing.
- **Testing in a real browser found what unit tests could not.** A headless Chrome viva with a fake microphone showed that Sarvam refuses Chrome's `audio/webm;codecs=opus` label and accepts only `audio/webm`; the codec label is now dropped in `speech.py`. Limits to know: Sarvam's Starter plan allows 60 speech-to-text requests a minute per account, enough for one batch answering at once but not three; speech to text costs ₹30 an hour of audio, and the ₹100 sign-up credit covers about one batch. Browsers allow the microphone only on https or localhost, so the lab pilot needs the app served over https.
